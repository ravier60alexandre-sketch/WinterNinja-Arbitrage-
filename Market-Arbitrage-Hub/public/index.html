ATO (Adaptive Threshold Optimizer)

Objective: ExpectedNet = (edge − fees − slippage − adverse_selection) × fill_rate × frequency
Guard Min: fees_bps + slippage_p50 + 1bps buffer
Guard Max: current P50
Sweep: Test each threshold from min to max by 0.5bps steps on 30min ring buffer
Recalibration: Every 30-60min (not continuous, avoids overfitting)

Regime Detector

🟢 Calm (σ < p25): Tight spread, few opportunities, predictable
🟡 Active (p25 ≤ σ ≤ p75): Normal conditions, good trading
🔴 Explosive (σ > p75): High vol, big opportunities, high slippage risk

1. Pipeline Complet

1
WebSocket Pool
Pool de 9 connexions WS multiplexées vers wss://api.hyperliquid.xyz/ws. Subscriptions L2 orderbook par coin, réparties automatiquement. Heartbeat 30s, reconnect exponentiel (1s → 30s max) avec jitter. Détection stale connection (60s sans données).
↓
2
Store / PairEngine
Chaque paire a son propre Store isolé avec RingBuffer, RollingStats et SpikeTracker. Le PairEngine reçoit les books via WS, appelle computeMetrics() à chaque tick, et propage les signaux aux ExecutionEngines (6 bots, routés par deployer + direction).
↓
3
Arbitrage Engine (arb.js)
Calcul VWAP multi-niveaux pour chaque notional (ex: $50). Fast-path rejection si best edge < 50% du seuil (skip VWAP coûteux). Filtres: capacité (depth), slippage max (bps), levels consumés, spike persistence (durée min).
↓
4
Signal Generation
Signal TRADEABLE émis si: edge brut ≥ feesRT + bufferBps, kalmanZ ≥ zThreshold, capacité OK, slippage OK, et spike persisté ≥ minSpikeMs. Signal routé vers le bot du deployer + direction correspondant.
↓
5
Execution Engine
Vérifications canTrade (guards), entry IOC parallèle sur 2 legs, gestion orphelins, TP dynamique, close queue par paire, reconciliation continue.
↓
6
HL API
Wrapper du SDK Hyperliquid. Injection dynamique des deployer perps (xyz, flx, km, cash, etc.) dans le SDK. Ordres IOC, gestion leverage, balances, positions on-chain, funding. Latency ring (50 entries) pour monitoring.
Signal Flow (Z-Score entry):
INSUFFICIENT_DEPTH → Z_CANDIDATE → Z Gate (kalmanZ ≥ threshold) → Tier Margin Check → EXECUTE
Entry modes: zscore, ou, kalman. TP = fees floor. Tier margin limit applied per-pair before execution.

2. Cycle de Vie d'un Trade

📡 Signal TRADEABLE
Edge brut ≥ feesRT + bufferBps ET kalmanZ ≥ zThreshold. Signal routé au bot correspondant.
↓
🛡 canTrade Guards
Bot enabled, pair enabled, tier margin limit (% collateral par paire), max global positions, coin cooldown, symbol cooldown, collatéral OK, deployer collateral OK, pending order lock.
↓
🚀 Entry (2 legs IOC en parallèle)
Promise.allSettled([legA, legB]) — ordres IOC avec prix calculé depuis le book live (VWAP best price + slippage). Si les 2 legs fill → trade enregistré en DB. Si 1 seule fill → orphelin (close après 25s). Si 0 fill → rien inséré.
↓
📊 TP Dynamique (Take Profit)
TP calculé selon la Close Strategy choisie. Le spread est surveillé en continu via checkAndClosePositions(). Quand le spread inverse atteint le TP → trade ajouté à la close queue.
↓
📤 Close Queue & Execution
Queue par paire, traitée séquentiellement. DB lock (status='closing') avant exécution. 2 legs IOC en parallèle. Si 1 leg miss → fallback avec slippage élargi. Fire-and-forget DB update pour vitesse.
↓
✅ PnL & Cleanup
PnL brut calculé (exit - entry par leg), fees calculées (entry + exit notional × pair fee rates). DB status='closed'. Mémoire nettoyée: openPositions, _openTradesCache, _openCoinSides, _closingCoins.

7. Formule PnL

Net PnL = Gross Trade PnL − Fees − Error Costs − DN Adjustment Costs + Wallet Funding
• Gross Trade PnL: SUM(realized_pnl_usd) WHERE status='closed' — PnL brut avant fees
• Fees: SUM(fees_usd) WHERE status IN ('closed','open') — entry + exit fees
• Error Costs: SUM(error_cost_usd) WHERE status IN ('error','orphan_closed','slippage_guard')
• DN Costs: SUM(error_cost_usd) WHERE status='dn_adjustment'
• Wallet Funding: Cumul des paiements funding reçus/payés via l'API HL (cache 5 min)

23. Vol-Adjusted Spread (Signed + Z-score/OU/Kalman)

Spread signé avec trois modes d'analyse statistique.

ModeFormuleInterprétation
Signed SpreadspreadBps = midA − midB (en bps)Positif = A cher (D2), négatif = B cher (D1). Convention directionnelle préservée.
Static Zz = (spread − rolling_mean) / rolling_std, window = 20 samplesz > +2 → fort signal D2 (vendre A, acheter B). z < −2 → fort signal D1.
OU (Ornstein-Uhlenbeck)Fit θ (vitesse retour), μ (moyenne), σ_ou. Plot (spread − μ) / σ_ouMontre la vitesse de mean-reversion. θ élevé = retour rapide à la moyenne.
KalmanFiltre Kalman 1D sur le spread. Plot (spread − kalman_estimate) / kalman_uncertaintyPlus lisse, adaptatif. Filtre le bruit de marché.
±2σ BandsLignes rouges pointillées à ±2 sur tous les modesZones d'opportunité de trading. Dépassement = signal potentiel.
